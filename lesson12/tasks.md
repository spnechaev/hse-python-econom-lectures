# Занятие 12. Задачи для самостоятельного решения

> **Домашняя работа.** В материалах курса приведены **предполагаемые списки домашних задач**. Домашние задания нужно решать и сдавать в **Яндекс.Контесте**. Актуальный список задач, условия и требования к оформлению находятся в Контесте. **При расхождениях информация в Контесте имеет приоритет.** Ссылки на контесты публикуются на **вики курса**.

Каждое решение — отдельный `.py` с указанной функцией. Задачи независимы. В этой работе используются NumPy и pandas: массивы и таблицы уже переданы функции, читать файлы и обращаться к сети не нужно. Не используйте `input()` и `print()`.

Исходные объекты не меняются. Денежные суммы храним в целых копейках. Схема таблиц и типы аргументов соответствуют описанию; отдельно проверяются перечисленные ошибки содержимого и формы массивов. Проверяется тип исключения `ValueError`, а не его текст. Лишних столбцов в таблицах нет; порядок входных столбцов и индекс могут быть любыми. Результат должен иметь заданный порядок столбцов и новый `RangeIndex`.

Для выходных таблиц используйте `string` для строк и `int64` для целых чисел, в том числе на пустом результате. Здесь `string` — явный строковый тип pandas (`astype("string")`), а не автоматическое угадывание типа. Во входных ключах ведущие нули значимы: `"001"` и `"1"` — разные товары. Ключи уже очищены от пробелов по краям; пустая строка или пропуск там, где они запрещены, должны быть замечены.

## Easy 1. Средняя цена одной проданной штуки

Реализуйте:

```python
import numpy as np

def weighted_price(prices_kopecks: np.ndarray, units: np.ndarray) -> float:
    ...
```

Два одномерных массива `int64` одинаковой длины содержат цену одной штуки и число проданных штук. Цены и количества неотрицательны; строки с нулевым количеством на результат не влияют. Нужна средняя цена **одной штуки**: общая выручка, делённая на общее количество. Не округляйте её до целой копейки.

Разная длина, размерность кроме одной, отрицательное число или нулевое суммарное количество — `ValueError`. Поэтому два пустых массива тоже нужно отклонить. Массивы не меняются. Используйте операции NumPy, без цикла по позициям.

Примеры:

```python
prices = np.array([100, 1000], dtype="int64")
units = np.array([9, 1], dtype="int64")
assert np.isclose(weighted_price(prices, units), 190.0)
assert np.isclose(weighted_price(np.array([0, 100]), np.array([3, 1])), 25.0)
assert np.isclose(weighted_price(np.array([500, 100]), np.array([0, 2])), 100.0)
```

Ограничения: до 100 000 позиций, цена до 10⁷ копеек, количество до 10⁵. Произведение и общая выручка помещаются в `int64`. Ответ сравнивается с `rtol=10⁻¹²`, `atol=10⁻⁹`.

Критерии: разный объём продаж учтён, цена 0 допустима, нулевой знаменатель отклонён, исходные массивы сохранены.

## Easy 2. Выручка по месяцам

Реализуйте:

```python
import pandas as pd

def monthly_sales(events: pd.DataFrame) -> pd.DataFrame:
    ...
```

Входные столбцы:

- `date` — дата pandas, уже преобразованная в datetime; возможен `NaT`;
- `revenue_kopecks` — целые суммы, включая отрицательные возвраты; возможны пропуски.

Если в любом из этих столбцов есть пропуск, нужен `ValueError`: считать неизвестную сумму нулём нельзя. Остальные значения корректны, дробей и бесконечностей нет. Верните `month`, `revenue_kopecks`, `events`: месяц строкой `YYYY-MM`, сумма за этот месяц и число исходных строк. Не группируйте только по номеру месяца: январь разных лет — разные группы.

Месяцы идут по возрастанию. Группа с нулевой суммой сохраняется. Пустой вход даёт пустую таблицу с нужными столбцами и типами: `string`, `int64`, `int64`.

Пример:

```python
source = pd.DataFrame({
    "date": pd.to_datetime(["2026-02-02", "2026-01-20", "2026-01-21", "2025-01-10"]),
    "revenue_kopecks": [50, 100, -100, 30],
})
expected = pd.DataFrame({
    "month": pd.Series(["2025-01", "2026-01", "2026-02"], dtype="string"),
    "revenue_kopecks": [30, 0, 50],
    "events": [1, 2, 1],
})
pd.testing.assert_frame_equal(monthly_sales(source), expected)
```

Ограничения: до 100 000 строк; суммы и итоги помещаются в `int64`. Исходный индекс значения не имеет и не должен попадать в группировку.

Критерии: годы различаются, возвраты уменьшают сумму, нулевой итог остаётся, число событий не подменяется суммой и исходная таблица не меняется.

## Easy 3. Присоединить справочник без потери строк

Реализуйте:

```python
import pandas as pd

def attach_catalog(lines: pd.DataFrame, products: pd.DataFrame) -> pd.DataFrame:
    ...
```

В `lines` столбцы `event_id`, `product_id`, `units`; в `products` — `product_id`, `unit_cost_kopecks`. Строковые столбцы имеют `string`, числа — `int64`. Количества уже положительны, стоимость закупки неотрицательна. Несколько строк `lines` могут относиться к одному товару.

Верните `event_id`, `product_id`, `units`, `unit_cost_kopecks` в исходном порядке строк `lines`, с новым `RangeIndex`. Нужно использовать соединение с отношением «многие к одному»: справочник даёт одну стоимость каждой строке.

Любой пропущенный или пустой `product_id` в любой таблице, повтор `product_id` в справочнике или неизвестный товар из `lines` — `ValueError`. Проверяется весь справочник, даже если `lines` пусты. Пустой справочник разрешён только при пустых `lines`. Сохранить неизвестную закупку как 0 или молча потерять строку нельзя. `event_id` уже заполнен и проверен.

Пример:

```python
lines = pd.DataFrame({
    "event_id": pd.Series(["e2", "e1", "e3"], dtype="string"),
    "product_id": pd.Series(["002", "001", "002"], dtype="string"),
    "units": [2, 1, 3],
})
products = pd.DataFrame({
    "product_id": pd.Series(["001", "002"], dtype="string"),
    "unit_cost_kopecks": [50, 80],
})
result = attach_catalog(lines, products)
assert result["event_id"].tolist() == ["e2", "e1", "e3"]
assert result["unit_cost_kopecks"].tolist() == [80, 50, 80]
assert len(result) == len(lines)
```

Ограничения: до 100 000 строк в каждой таблице. Не превращайте идентификаторы в числа и не ищите каждый товар отдельным циклом по справочнику. Для обнаружения размножения строк подходит `validate="many_to_one"`, для неизвестных ключей — `indicator=True`.

Критерии: сохранены порядок и число событий, повтор справочника и отсутствие товара замечены, входы не изменены, ведущие нули не потеряны.

## Medium 1. Продажи и возвраты в одном своде

Реализуйте:

```python
import pandas as pd

def net_sales_report(events: pd.DataFrame, products: pd.DataFrame) -> pd.DataFrame:
    ...
```

В `events` шесть столбцов: `event_id`, `channel`, `product_id`, `event`, `units`, `unit_price_kopecks`. Первые четыре строковые (`string`), два последних числовые: целые или вещественные, в том числе nullable-столбцы pandas. В `products` — строковый `product_id` и числовой `unit_cost_kopecks`. Числовые строки разбирать не нужно.

Перед расчётом проверьте **все строки**, включая отменённые:

- строковые поля заполнены и не пусты, `event_id` уникален во всём входе;
- `event` — одно из `sale`, `return`, `cancelled`;
- количество — конечное целое число строго больше нуля;
- цена и закупка — конечные целые числа не меньше нуля; нулевая цена разрешена;
- ключ справочника непустой, уникальный, каждый товар события найден в справочнике.

Любое нарушение — `ValueError`, без изменения входов. В этой задаче повторы уже не исправляются: даже две одинаковые строки с одним `event_id` считаются ошибкой. До вызова функции не было правила, которое разрешало бы отбросить одну из них.

После проверки отмены исключаются. Продажа даёт плюс к количеству, выручке и закупке; возврат — минус. Возврат записан с положительным `units` и своей фактической ценой возврата. Считаем, что возвращённый товар снова пригоден для продажи, а стоимость закупки в пределах задачи не менялась. Проверять соответствие возврата конкретной прежней продаже не требуется.

Соберите результат по `channel`: `net_units`, `revenue_kopecks`, `cogs_kopecks`, `gross_margin_kopecks`, где маржа — выручка минус стоимость товара. Сначала идёт столбец `channel` (`string`), затем четыре `int64`. Каналы отсортированы по возрастанию, индекс — `RangeIndex`.

Канал с продажами или возвратами остаётся даже при нулевом итоге. Канал только с отменами не попадает в результат. Отрицательная маржа допустима. Если после исключения отмен ничего не осталось, верните пустой результат с заданными типами. Это маржа после стоимости товара, **не чистая прибыль**: реклама, аренда, зарплаты и налоги не заданы.

Пример:

```python
events = pd.DataFrame({
    "event_id": ["e1", "e2", "e3", "e4"],
    "channel": ["поиск", "поиск", "прямой", "соцсети"],
    "product_id": ["001", "001", "002", "001"],
    "event": ["sale", "return", "sale", "cancelled"],
    "units": [2, 1, 1, 4],
    "unit_price_kopecks": [100, 100, 0, 100],
})
events[["event_id", "channel", "product_id", "event"]] = events[["event_id", "channel", "product_id", "event"]].astype("string")
products = pd.DataFrame({
    "product_id": pd.Series(["001", "002"], dtype="string"),
    "unit_cost_kopecks": [60, 20],
})
expected = pd.DataFrame({
    "channel": pd.Series(["поиск", "прямой"], dtype="string"),
    "net_units": [1, 1],
    "revenue_kopecks": [100, 0],
    "cogs_kopecks": [60, 20],
    "gross_margin_kopecks": [40, -20],
})
pd.testing.assert_frame_equal(net_sales_report(events, products), expected)
```

Ограничения: до 100 000 событий и товаров, количество до 1000, цена и закупка до 10⁷ копеек. Все произведения и итоговые суммы помещаются в `int64`. Используйте табличные операции и группировку, без построчного поиска товара в справочнике и без `apply(axis=1)` для арифметики.

Критерии: отмены не маскируют ошибки входа, соединение не размножает события, знак возврата применён и к выручке, и к закупке, результат и исходные таблицы имеют оговорённый вид.

## Medium 2. Скидка должна окупиться количеством

Реализуйте:

```python
import numpy as np

def discount_scenarios(
    unit_price_kopecks: int,
    unit_cost_kopecks: int,
    discounts: np.ndarray,
    quantities: np.ndarray,
) -> np.ndarray:
    ...
```

Цена и закупка одной штуки неотрицательны. `discounts` — одномерный `int64` с целыми процентами от 0 до 100; `quantities` — одномерный `int64` с неотрицательными объёмами продаж. Нарушение этих условий, включая неправильную размерность, — `ValueError`.

Цена после скидки считается для **одной штуки**: `unit_price_kopecks * (100 - discount) // 100`. Сначала округлите её вниз до целой копейки, затем вычтите закупку и умножьте на количество. Округлять всю общую выручку только в конце было бы другим правилом.

Результат — новый двумерный массив `int64` формы `(len(discounts), len(quantities))`. Каждая строка соответствует скидке в исходном порядке, каждый столбец — количеству. Повторяющиеся и неотсортированные значения допустимы. Отрицательный остаток после закупки сохраняется. Для пустого массива скидок или количеств верните массив соответствующей пустой формы, например `(0, 3)` или `(2, 0)`.

Пример:

```python
result = discount_scenarios(
    40000, 32000,
    np.array([0, 5, 10], dtype="int64"),
    np.array([100, 110, 130], dtype="int64"),
)
np.testing.assert_array_equal(result, np.array([
    [800000, 880000, 1040000],
    [600000, 660000, 780000],
    [400000, 440000, 520000],
], dtype="int64"))
assert discount_scenarios(101, 50, np.array([10]), np.array([3]))[0, 0] == 120
```

Ограничения: цена и закупка до 10⁹ копеек, количество до 10⁶, длина каждого массива до 2000. Вычисления помещаются в `int64`. Используйте broadcasting: построчный Python-цикл и `np.vectorize` для этой задачи не подходят. Входные массивы не меняются.

Критерии: оси не перепутаны, округление выполнено на единицу товара, скидка 100%, нулевой объём и пустые формы поддержаны, отрицательный результат не спрятан.

Это сравнение заданных сценариев, **не прогноз спроса**. Модель не знает, сколько покупателей появится из-за скидки. Реклама, аренда и другие затраты здесь не учтены.
