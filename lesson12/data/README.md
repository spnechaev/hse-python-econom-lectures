# Учебная выгрузка магазина

Это **синтетические данные**, подготовленные для занятия. Они не описывают реальную компанию, её клиентов или результаты рекламы. Небольшие суммы и число строк позволяют проверить расчёт вручную.

Все три CSV имеют разделитель `;` и кодировку UTF-8 с BOM. При чтении подходит `encoding="utf-8-sig"`. Идентификаторы — строки: ведущие нули значимы. Начинать удобно с `dtype="string"`, затем отдельно разбирать числа и даты. В файлах нет переносов строк внутри полей.

## Что лежит в файлах

### `transactions.csv`

Одна строка — **событие по одной товарной позиции**, а не заказ целиком. В одном заказе может быть несколько строк; возврат — новое событие с прежним `order_id`.

| Поле | Смысл |
| --- | --- |
| `event_id` | Идентификатор события, например `000001` |
| `date` | Дата события в формате `YYYY-MM-DD`; период кейса — январь и февраль 2026 года |
| `order_id` | Идентификатор заказа |
| `product_id` | Код товара из справочника |
| `channel` | Приписанный выгрузкой канал: `поиск`, `соцсети`, `прямой` |
| `event` | `sale`, `return` или `cancelled` |
| `units` | Положительное целое число единиц |
| `unit_price_kopecks` | Фактическая цена за единицу в целых копейках, включая допустимый ноль |

Выгрузка намеренно содержит повторы и испорченные записи. Пустое количество не означает ноль. Цена ноль, напротив, допустима: в феврале есть отдельная строка подарка.

Вид события определяет знак расчёта:

- `sale`: положительное количество, неотрицательные выручка и стоимость проданного товара;
- `return`: отрицательное количество, неположительные выручка и стоимость товара;
- `cancelled`: корректная отменённая заявка, которая не входит в финансовый расчёт.

В кейсе возвращают целую ранее проданную позицию по её фактической цене. Товар после возврата снова пригоден к продаже; его стоимость восстанавливается. Себестоимость товара в течение двух месяцев считаем постоянной. Это упрощение учебной модели, а не универсальное правило учёта любых возвратов. Дата относится к событию: она может отличаться от даты создания заказа и других его позиций.

### `products.csv`

Справочник с колонками `product_id`, `product_name`, `unit_cost_kopecks`. Код товара уникален, себестоимость — неотрицательное целое число копеек. Все четыре товара нужны для проверки состава продаж: чайник, кабель, лампа и кружка.

### `advertising.csv`

Колонки: `month`, `channel`, `ad_spend_kopecks`. Пара `(month, channel)` уникальна. В таблице явно записаны все шесть сочетаний двух месяцев и трёх каналов, включая нулевые расходы прямого канала.

В феврале у соцсетей есть рекламный расход, хотя ни одной финансовой строки с таким каналом нет. Такой расход нельзя потерять при соединении. Если для группы нет событий, суммы продаж известны и равны нулю. Если отсутствует обязательная строка расходов, её значение **неизвестно**: подставлять ноль без проверки нельзя.

Рекламу нужно присоединять к уже собранным итогам по `(month, channel)`. Если соединить месячный бюджет с каждой товарной строкой и затем сложить его, один расход будет посчитан несколько раз.

## Правила проверки выгрузки

Порядок действий важен:

1. Убрать пробелы по краям всех текстовых полей.
2. Удалить полные совпадения по **всем восьми исходным колонкам**. Служебный номер строки в сравнение не входит. Сохранить первую запись и число удалённых повторов.
3. Если после этого один `event_id` встречается несколько раз, отложить **все** его версии как конфликт. Выбирать первую цену без выяснения причины нельзя.
4. У остальных проверить непустые идентификаторы, известные вид события и канал, корректную дату, положительное целое количество, неотрицательную целую цену и наличие товара в справочнике. Справочник перед соединением также проверяется на уникальность ключа.
5. В журнале отказов сохранить исходный номер CSV-строки и причину. Здесь `source_row=2` — первая запись после заголовка. После удаления строк номера не пересчитываются.
6. Отмены учесть отдельно, остальные корректные события включить в финансовый расчёт с нужным знаком.

В `expected.json` причины записаны короткими кодами: `conflicting_event_id`, `invalid_date`, `invalid_units`, `unknown_product`, `invalid_price`, `invalid_event`. Сообщения для человека могут быть длиннее. В шести обычных испорченных строках по одному дефекту, поэтому порядок проверки не меняет их отнесение к причинам.

## Что считать результатом

`expected.json` содержит контрольные количества строк и итоговые таблицы. Суммы в нём по-прежнему в **копейках**:

- `units` — количество продаж за вычетом возвратов;
- `revenue_kopecks` — выручка за вычетом возвратов;
- `cogs_kopecks` — стоимость проданных товаров за вычетом стоимости возвращённых;
- `gross_margin_kopecks` — разность этих двух сумм;
- `after_ads_kopecks` — та же разность после учтённой рекламы.

Последний показатель **не является чистой прибылью**: аренда, зарплаты, налоги, комиссии, доставка и другие расходы здесь не заданы. Показываем только тот расчётный остаток, который можно обоснованно вычислить из имеющихся трёх таблиц. Это не движение денег на счёте: закупки могли оплатить раньше, а восстановленная стоимость возвращённого товара ещё не означает денежного поступления.

`weighted_sale_unit_price_by_month` относится только к событиям `sale`. Средняя цена одной проданной единицы — сумма `units * unit_price_kopecks`, делённая на число проданных единиц. `mean_row_price_kopecks` даёт среднее по строкам и не учитывает разные количества. Это средние для **состава продаж**, не индекс цен: более дешёвые кабели и подарок меняют среднюю даже при неизменных ценах платных позиций.

Канал — атрибуция из выгрузки, а не результат эксперимента. Ноль приписанных продаж не доказывает, что реклама не повлияла на покупки в других каналах или месяцах. Сравнение итогов помогает поставить следующий вопрос, но само по себе не измеряет причинный эффект рекламы.

## Воспроизводимость

Пересоздать три CSV из корня репозитория:

```bash
python3 lesson12/data/generate_data.py
```

Генератор детерминирован, не требует сети или дополнительных пакетов и не меняет контрольные итоги `expected.json`. Контрольные итоги рассчитаны независимым проходом средствами стандартной библиотеки; это результаты для сверки, а не решение семинарских или домашних задач.
