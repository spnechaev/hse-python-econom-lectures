# Занятие 11. Задачи для самостоятельного решения

> **Домашняя работа.** В материалах курса приведены **предполагаемые списки домашних задач**. Домашние задания нужно решать и сдавать в **Яндекс.Контесте**. Актуальный список задач, условия и требования к оформлению находятся в Контесте. **При расхождениях информация в Контесте имеет приоритет.** Ссылки на контесты публикуются на **вики курса**.

Каждое решение — один файл `.py` с указанными классами. Задачи независимы: импортировать решения других задач не нужно. Только стандартная библиотека, без файлов, сети, `input()` и `print()`.

Типы аргументов соответствуют описанию. Проверяйте перечисленные ошибки содержимого; проверяется тип исключения, а не точный текст. Все денежные суммы — целые копейки. Методы изменения состояния возвращают `None`, если другой результат не указан. Свойства только для чтения не имеют setter; намеренное изменение внутренних атрибутов с `_` не рассматривается.

Объекты-зависимости передаются готовыми. Их методы могут вести журнал вызовов, поэтому соблюдайте оговорённый порядок и число обращений. Не проверяйте имя класса зависимости и не создавайте вместо неё собственную реализацию. Общие родительские классы, `ABC` и `Protocol` не требуются, кроме явно указанного наследования в Easy 3.

## Easy 1. Два правила скидки

Один покупатель платит полную стоимость, у другого есть процентная скидка. Напишите два независимых класса с методом `apply(amount) -> int`:

```python
class NoDiscount:
    def apply(self, amount: int) -> int:
        ...


class PercentDiscount:
    def __init__(self, percent: int) -> None:
        ...

    def apply(self, amount: int) -> int:
        ...
```

`NoDiscount()` возвращает исходную сумму. `PercentDiscount(percent)` хранит целый процент от 0 до 100 включительно, иначе поднимает `ValueError`. После скидки покупатель платит `amount * (100 - percent) // 100`: округление идёт вниз до целой копейки. Используйте целочисленную арифметику.

Оба `apply` принимают неотрицательную сумму, включая ноль. Отрицательная сумма — `ValueError`. Правило можно вызывать много раз; расчёт не меняет его настройки. Два объекта скидки не делят настройки.

Примеры:

```python
regular = NoDiscount()
sale = PercentDiscount(25)
assert regular.apply(101) == 101
assert sale.apply(101) == 75
assert sale.apply(0) == 0
assert PercentDiscount(0).apply(101) == 101
assert PercentDiscount(100).apply(101) == 0
assert sale.apply(101) == 75

for rule in [regular, sale]:
    try:
        rule.apply(-1)
    except ValueError:
        pass
    else:
        raise AssertionError("Отрицательная сумма недопустима")
```

Ограничения: суммы по модулю до 10¹², до 100 000 вызовов. Создание и один расчёт — `O(1)` времени и памяти.

Критерии: обе реализации соблюдают один договор, границы процента проверены, нулевая сумма и полная скидка работают, результат вычислен без `float`.

## Easy 2. Расчёт получает готовую скидку

Напишите `BillCalculator(discount)`. Переданный объект имеет метод `apply(amount) -> int`: для неотрицательной суммы он возвращает итог от 0 до `amount` включительно либо поднимает исключение.

```python
class BillCalculator:
    def __init__(self, discount) -> None:
        ...

    def total(self, prices: list[int]) -> int:
        ...
```

`total(prices)` проверяет, что все цены неотрицательны, складывает их и передаёт сумму в `discount.apply` **ровно один раз**. Возвращает полученный итог. Пустой список разрешён: это расчёт для суммы 0, и зависимость всё равно вызывается один раз.

Если хотя бы одна цена отрицательна, нужен `ValueError` до вызова зависимости. Исходный список не меняется и не сохраняется для будущих расчётов. Исключение из `apply` передаётся дальше. Храните ссылку на переданный объект: изменение его настроек должно быть видно следующему расчёту.

Примеры:

```python
class RecordingDiscount:
    def __init__(self):
        self.calls = []
        self.reduction = 10

    def apply(self, amount):
        self.calls.append(amount)
        return max(0, amount - self.reduction)


discount = RecordingDiscount()
calculator = BillCalculator(discount)
prices = [100, 50]
assert calculator.total(prices) == 140
assert prices == [100, 50]
assert discount.calls == [150]
discount.reduction = 0
assert calculator.total([20]) == 20
assert calculator.total([]) == 0
assert discount.calls == [150, 20, 0]

try:
    calculator.total([10, -1, 20])
except ValueError:
    pass
else:
    raise AssertionError("Все цены проверяются до обращения к скидке")
assert discount.calls == [150, 20, 0]
```

Ограничения: до 100 000 цен в одном вызове и до 200 000 цен суммарно; цены по модулю до 10¹². Собственная работа `total` — `O(n)` времени и `O(1)` дополнительной памяти, без учёта зависимости.

Критерии: работает любая зависимость с нужным поведением, нет обращения к скидке на плохом входе, результат 0 не теряется, список не меняется.

## Easy 3. Товар с дополнительными сведениями

Напишите `Product(name, price_kopecks)` и его наследника `WeightedProduct(name, price_kopecks, weight_grams)`.

```python
class Product:
    def __init__(self, name: str, price_kopecks: int) -> None:
        ...

    @property
    def name(self) -> str:
        ...

    @property
    def price_kopecks(self) -> int:
        ...

    def total(self, count: int) -> int:
        ...


class WeightedProduct(Product):
    def __init__(self, name: str, price_kopecks: int, weight_grams: int) -> None:
        ...

    @property
    def weight_grams(self) -> int:
        ...
```

`Product` убирает пробелы по краям названия. Пустое после очистки название или отрицательная цена — `ValueError`. Свойства `name` и `price_kopecks` доступны только для чтения. `total(count)` возвращает цену указанного неотрицательного числа одинаковых упаковок. Ноль разрешён, отрицательное число — `ValueError`.

`WeightedProduct` — такой же товар, у которого дополнительно известен вес **одной упаковки**. Вес должен быть строго положительным, иначе нужен `ValueError`. Используйте `super().__init__` для общей инициализации. Свойства и метод `total` наследуются с прежним поведением; переопределять их не нужно. Новое свойство `weight_grams` — только для чтения. Цена относится к целой упаковке и не пересчитывается по весу.

Примеры:

```python
plain = Product(" пакет ", 30)
weighted = WeightedProduct(" чай ", 200, 100)
assert isinstance(weighted, Product)
assert (plain.name, plain.price_kopecks) == ("пакет", 30)
assert (weighted.name, weighted.price_kopecks, weighted.weight_grams) == ("чай", 200, 100)
assert weighted.total(3) == 600
assert weighted.total(0) == 0
assert plain.total(2) == 60
assert Product("образец", 0).total(10) == 0

try:
    weighted.total(-1)
except ValueError:
    pass
else:
    raise AssertionError("Число упаковок неотрицательно")
```

Ограничения: название до 100 символов; числа по модулю до 10⁹; до 100 000 объектов и вызовов суммарно. Создание требует `O(len(name))`, остальные операции — `O(1)` времени; память экземпляра — `O(len(name))` с учётом строки.

Критерии: общая часть инициализации передана родительскому методу, наследник соблюдает прежние правила товара и добавляет собственный вес, публичное присваивание свойствам запрещено.

## Medium 1. Чек проходит через три объекта

Напишите `ReceiptService(discount, formatter, sink)`. У сервиса один публичный метод — `issue(prices) -> int`.

```python
class ReceiptService:
    def __init__(self, discount, formatter, sink) -> None:
        ...

    def issue(self, prices: list[int]) -> int:
        ...
```

Зависимости соблюдают такие договоры:

- `discount.apply(subtotal) -> int` принимает неотрицательную сумму и возвращает итог от 0 до `subtotal`;
- `formatter.format(subtotal, total) -> str` получает сумму до скидки и после неё, возвращает готовый текст;
- `sink.write(text) -> None` принимает строку. Это может быть просто объект со списком записей в памяти.

Все цены в `prices` должны быть неотрицательными. Если встретилась отрицательная, поднимите `ValueError` до вызова любой зависимости. Входной список не меняется. Пустой список — допустимый чек с исходной суммой 0.

После проверки нужно последовательно выполнить ровно по одному вызову: скидка, форматтер, получатель. Получателю передаётся строка форматтера без переделки. `issue` возвращает итоговую сумму после скидки, включая ноль. Не требуйте от получателя методов `close`, `flush` или работы с файлами.

Если зависимость поднимает исключение, передайте **то же исключение** дальше и не вызывайте следующие этапы. Уже выполненные действия зависимостей не отменяются: например, если получатель записал текст и сам поднял ошибку, сервис не обещает убрать запись. У самого сервиса нет журнала или счётчика успешных чеков.

Пример:

```python
events = []

class Discount:
    def apply(self, subtotal):
        events.append(("discount", subtotal))
        return subtotal // 2

class Formatter:
    def format(self, subtotal, total):
        events.append(("format", subtotal, total))
        return f"Было {subtotal}, к оплате {total}"

class Sink:
    def write(self, text):
        events.append(("write", text))

service = ReceiptService(Discount(), Formatter(), Sink())
assert service.issue([101, 100]) == 100
assert events == [
    ("discount", 201),
    ("format", 201, 100),
    ("write", "Было 201, к оплате 100"),
]
```

Ограничения: до 100 000 цен в одном чеке, до 200 000 суммарно; цены по модулю до 10¹². Собственная работа сервиса — `O(n)` времени и `O(1)` дополнительной памяти, без учёта работы и результатов зависимостей.

Критерии: валидация предшествует зависимостям, порядок и аргументы вызовов соблюдены, нулевые результаты передаются, ошибка не превращается в успешный возврат, лишних требований к зависимостям нет.

## Medium 2. Сначала проверить заказ, потом занять остаток

На складе хватает каждого товара по отдельности. Но в заявке один товар может встретиться несколько раз: две строки по три пачки требуют шесть пачек. Сначала соберём полную потребность, узнаем цены и только потом займём остаток.

Реализуйте два класса:

```python
class Stock:
    def __init__(self, quantities: dict[str, int]) -> None:
        ...

    def available(self, name: str) -> int:
        ...

    def reserve(self, requested: dict[str, int]) -> None:
        ...

    def snapshot(self) -> dict[str, int]:
        ...


class OrderService:
    def __init__(self, stock, price_book) -> None:
        ...

    def place(self, lines: list[tuple[str, int]]) -> int:
        ...
```

Названия товаров гарантированно непустые строки без пробелов по краям. Начальные остатки должны быть неотрицательными; отрицательный остаток при создании означает `ValueError`. `Stock` копирует исходный словарь. `snapshot()` каждый раз возвращает новую копию, `available(name)` — остаток; неизвестный товар означает `KeyError`.

`reserve(requested)` принимает потребность по разным товарам. Пустая потребность разрешена. В каждой паре количество должно быть строго положительным, иначе нужен `ValueError`. Неизвестный товар означает `KeyError`, нехватка остатка — `ValueError`. **Вся потребность проверяется до изменения любого остатка.** При любой из этих ошибок склад сохраняется целиком. При успехе запрошенные количества вычитаются; товары с нулевым остатком остаются в словаре. Переданный словарь `requested` не меняется и не становится внутренним состоянием склада. Порядок проверок разных ошибочных пар не задан: если нарушений несколько, допустимо любое соответствующее исключение.

У `price_book` нужен только метод `price(name) -> int`. Он возвращает неотрицательную цену одной единицы либо поднимает исключение. Метод не меняет переданный склад. `OrderService` хранит ссылки на переданные зависимости. От склада ему нужен только `reserve(requested) -> None`; можно передать другой объект с этим методом и тем же договором об успехе и отказе.

`place(lines)` работает так:

1. Проверяет количество во **всех** строках: оно строго положительно. При нарушении — `ValueError` без обращения к зависимостям.
2. Складывает количества повторяющихся товаров. Исходный список не меняет.
3. Получает цену ровно один раз для каждого различного товара, в порядке его первого появления. По цене и общему количеству считает итог.
4. После получения всех цен один раз вызывает `stock.reserve` с полной потребностью и возвращает итог.

Пустая заявка возвращает 0 без вызова `price_book.price` и `stock.reserve`. Исключения зависимостей не перехватываются. Если получение цены не удалось, резерв ещё не выполнялся и склад не изменён. Если резерв отклонён, его собственный договор сохраняет весь склад. Вызовы книги цен могли уже состояться; откат их внутреннего журнала не требуется.

Примеры:

```python
class PriceBook:
    def __init__(self, prices):
        self.prices = prices
        self.calls = []

    def price(self, name):
        self.calls.append(name)
        return self.prices[name]

initial = {"чай": 5, "хлеб": 2}
stock = Stock(initial)
initial["чай"] = 100
assert stock.available("чай") == 5
book = PriceBook({"чай": 100, "хлеб": 30})
service = OrderService(stock, book)
lines = [("чай", 2), ("хлеб", 1), ("чай", 1)]
assert service.place(lines) == 330
assert book.calls == ["чай", "хлеб"]
assert stock.snapshot() == {"чай": 2, "хлеб": 1}
assert lines == [("чай", 2), ("хлеб", 1), ("чай", 1)]

before = stock.snapshot()
try:
    service.place([("чай", 1), ("хлеб", 2)])
except ValueError:
    pass
else:
    raise AssertionError("Нельзя занять больше хлеба, чем осталось")
assert stock.snapshot() == before

view = stock.snapshot()
view.clear()
assert stock.snapshot() == before
assert service.place([]) == 0
```

Ограничения: до 100 000 товаров на складе и до 100 000 строк в заявке; длина названия до 100 символов; остатки, количества и цены по модулю до 10⁹. Операции словаря оцениваем в среднем при хорошем распределении хешей. Создание склада и его копирование — `O(s)`; `available` — ожидаемая `O(1)`; `reserve` — ожидаемая `O(k)` по размеру потребности. `place` — ожидаемое `O(n + k)` времени и `O(k)` дополнительной памяти, без учёта работы книги цен, где `k` — число разных товаров в заявке.

Критерии: повторы агрегируются до резерва, книга цен вызывается один раз на различный товар, исходные коллекции не открывают доступ к состоянию склада, ошибка не оставляет частичного списания, два сервиса могут пользоваться одним переданным складом.
