Все функции должны возвращать результат, а не печатать его. Не изменяйте переданные коллекции, если условие прямо не разрешает обратное.

## Easy 1. Чистые цены

Реализуйте функцию:

```python
def clean_prices(values: list[int | float | None]) -> list[float]:
    ...
```

Функция должна удалить значения `None`, преобразовать числа в `float` и сохранить исходный порядок. Значения типа `bool` необходимо отвергать исключением `TypeError`, несмотря на то что `bool` является подклассом `int`.

Примеры:

```python
clean_prices([10, None, 12.5, 8]) == [10.0, 12.5, 8.0]
clean_prices([]) == []
```

Ограничения:

- длина списка не превосходит `10_000`;
- входной список изменять нельзя;
- при первом значении `bool` нужно выбросить `TypeError`.

Критерии проверки:

- корректная фильтрация `None`;
- явное различение `bool` и чисел;
- сохранение порядка и неизменность аргумента.

## Easy 2. Уникальные категории

Реализуйте функцию:

```python
def unique_categories(categories: list[str]) -> list[str]:
    ...
```

Нужно удалить повторения без изменения порядка первых появлений. Регистр имеет значение, пробелы не удаляются.

Пример:

```python
unique_categories(["food", "taxi", "food", "Food", "taxi"])
# ["food", "taxi", "Food"]
```

Ограничения:

- до `100_000` элементов;
- каждый элемент является строкой;
- нельзя сортировать входные данные.

Критерии проверки:

- правильный порядок;
- отсутствие повторений;
- решение не должно выполнять полный линейный поиск по уже построенному результату для каждого элемента.

## Easy 3. Точная сумма

Реализуйте функцию:

```python
def exact_total(amounts: list[int]) -> int:
    ...
```

Каждый элемент — денежная сумма в целых копейках. Верните общую сумму в копейках. Отрицательные значения означают списания.

Примеры:

```python
exact_total([10, 20]) == 30
exact_total([]) == 0
exact_total([1050, -225, 175]) == 1000
```

Ограничения:

- до `100_000` значений;
- все значения имеют тип `int` и заданы в копейках;
- форматировать или округлять результат не требуется.

Критерии проверки:

- результат имеет тип `int`;
- положительные и отрицательные суммы учитываются корректно;
- пустой список обрабатывается корректно.

## Medium 1. Слияние остатков

Реализуйте функцию:

```python
def merge_balances(
    current: dict[str, int],
    changes: dict[str, int],
) -> dict[str, int]:
    ...
```

Остатки и изменения заданы целыми числами копеек. Для каждого счёта из `changes` прибавьте изменение к текущему остатку. Если счёта ещё нет, его исходный остаток равен нулю. Счета, отсутствующие в `changes`, должны сохраниться. Словари-аргументы изменять нельзя.

Пример:

```python
current = {"cash": 10_000, "deposit": 50_000}
changes = {"cash": -1550, "broker": 2500}

merge_balances(current, changes) == {
    "cash": 8450,
    "deposit": 50_000,
    "broker": 2500,
}
```

Ограничения:

- суммарно не более `200_000` ключей;
- все значения имеют тип `int` и заданы в копейках;
- порядок ключей результата не проверяется.

Критерии проверки:

- корректная обработка общих и новых счетов;
- исходные словари остаются неизменными;
- в результате нет общих изменяемых значений с аргументами.

## Medium 2. Независимый сценарий бюджета

Реализуйте функцию:

```python
Budget = dict[str, list[int]]

def with_scenario(
    budget: Budget,
    category: str,
    month: int,
    value: int,
) -> Budget:
    ...
```

Все суммы в бюджете и аргумент `value` заданы целыми числами копеек. Функция должна вернуть новый бюджет, в котором значение выбранной категории за указанный месяц заменено на `value`. Исходный бюджет и все вложенные в него списки должны остаться неизменными.

Пример:

```python
source = {
    "revenue": [10_000, 11_000],
    "costs": [7000, 7500],
}

scenario = with_scenario(source, "costs", 1, 9000)

scenario["costs"] == [7000, 9000]
source["costs"] == [7000, 7500]
scenario["revenue"] == source["revenue"]
scenario["revenue"] is not source["revenue"]
```

Если категории нет, выбросьте `KeyError`. Если индекс месяца выходит за границы списка, выбросьте `IndexError`.

Ограничения:

- до `1_000` категорий;
- в каждой категории до `1_000` месяцев;
- использовать `copy.deepcopy` нельзя: требуемое копирование нужно реализовать осознанно.

Критерии проверки:

- корректное изменение выбранного значения;
- полная независимость всех вложенных списков результата;
- исходная структура не изменяется;
- предусмотренные исключения сохраняют стандартные типы.

## Hard 1. Первое отсутствующее положительное число

Задача основана на [LeetCode 41. First Missing Positive](https://leetcode.com/problems/first-missing-positive/description/).

Дан неотсортированный список целых чисел. Реализуйте функцию:

```python
def first_missing_positive(nums: list[int]) -> int:
    ...
```

Верните наименьшее положительное целое число, которого нет в списке.

Примеры:

```python
first_missing_positive([1, 2, 0]) == 3
first_missing_positive([3, 4, -1, 1]) == 2
first_missing_positive([7, 8, 9, 11, 12]) == 1
first_missing_positive([1, 1]) == 2
```

Ограничения:

- `1 <= len(nums) <= 100_000`;
- элементы находятся в диапазоне 32-битных знаковых целых чисел;
- требуемая сложность — `O(N)` по времени и `O(1)` дополнительной памяти;
- использовать `set`, `dict`, сортировку или дополнительный список размера `O(N)` нельзя;
- **в этой задаче входной список разрешено изменять**.

Полезное наблюдение: для списка длины `N` ответ всегда находится в диапазоне от `1` до `N + 1`. Сам список можно использовать как структуру для учёта присутствующих значений.

Критерии проверки:

- корректная работа с отрицательными числами, нулём и повторами;
- каждый элемент обрабатывается амортизированно константное число раз;
- после перестановок значение `x` из диапазона `1..N` можно связать с индексом `x - 1`;
- соблюдаются `O(N)` по времени и `O(1)` дополнительной памяти.
