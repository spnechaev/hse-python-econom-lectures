# Занятие 06. Задачи для самостоятельного решения

Каждое решение оформляется как функция с указанной сигнатурой. Функция возвращает результат и не использует `input` или `print`.

## Easy 1. Очередь платежей

Платёж представлен словарём с полями `id`, `priority` и `created_at`:

```python
{"id": "p-17", "priority": 2, "created_at": "09:30"}
```

Реализуйте функцию:

```python
def order_payments(payments: list[dict]) -> list[dict]:
    ...
```

Верните новый список: сначала идут платежи с большей `priority`, а внутри одинакового приоритета — с меньшим `created_at`. Исходный список не изменяйте.

Пример:

```python
payments = [
    {"id": "a", "priority": 1, "created_at": "09:00"},
    {"id": "b", "priority": 3, "created_at": "10:00"},
    {"id": "c", "priority": 3, "created_at": "08:30"},
]
assert [item["id"] for item in order_payments(payments)] == ["c", "b", "a"]
```

Ограничения:

- `0 <= len(payments) <= 100_000`;
- время записано в формате `HH:MM`;
- использовать `sorted()` и `key`.

Критерии проверки:

- приоритет сортируется по убыванию, время — по возрастанию;
- исходный список не изменяется;
- ключ вычисляется из одной записи;
- временная сложность `O(N log N)` в худшем случае.

## Easy 2. Стабильная группировка заявок

Заявка представлена парой `[status, id]`. Порядок статусов задан отдельно, например `order = ["new", "in_progress", "done"]`.

Реализуйте:

```python
def group_requests(requests: list[list[str]], order: list[str]) -> list[list[str]]:
    ...
```

Верните заявки, сгруппированные по порядку статусов. Внутри одного статуса исходный порядок должен сохраниться.

Пример:

```python
requests = [
    ["done", "r1"],
    ["new", "r2"],
    ["done", "r3"],
    ["new", "r4"],
]
group_requests(requests, ["new", "done"]) == [
    ["new", "r2"],
    ["new", "r4"],
    ["done", "r1"],
    ["done", "r3"],
]
```

Ограничения:

- все статусы присутствуют в `order`;
- `0 <= len(requests) <= 100_000`;
- использовать стабильность встроенной сортировки.

Критерии проверки:

- группы расположены в заданном порядке;
- относительный порядок равных ключей не меняется;
- исходный список не изменяется.

## Easy 3. Сортировка вставками

Реализуйте:

```python
def insertion_sort(values: list[int]) -> list[int]:
    ...
```

Верните новый список, отсортированный по возрастанию алгоритмом insertion sort. `sorted()` и `.sort()` использовать нельзя.

Примеры:

```python
insertion_sort([]) == []
insertion_sort([5, 2, 4, 2]) == [2, 2, 4, 5]
insertion_sort([1, 2, 3]) == [1, 2, 3]
```

Ограничения:

- `0 <= len(values) <= 5_000`;
- исходный список не изменяется.

Критерии проверки:

- перед каждой итерацией префикс уже отсортирован;
- элементы сдвигаются, а не обмениваются со всеми предыдущими подряд;
- лучший случай `Θ(N)`, худший `Θ(N²)`;
- дополнительная память результата не учитывается, сверх копии используется `O(1)`.

## Medium 1. Сортировка слиянием

Реализуйте:

```python
def merge_sort(values: list[int]) -> list[int]:
    ...
```

Верните новый отсортированный список. `sorted()` и `.sort()` запрещены.

Примеры:

```python
merge_sort([]) == []
merge_sort([7]) == [7]
merge_sort([5, 1, 4, 1, 3]) == [1, 1, 3, 4, 5]
```

Ограничения:

- `0 <= len(values) <= 200_000`;
- слияние двух отсортированных частей выполняется линейно;
- рекурсивное разбиение должно завершаться на длине `0` или `1`.

Критерии проверки:

- результат содержит те же элементы с теми же кратностями;
- временная сложность `Θ(N log N)`;
- максимальная дополнительная память `O(N)` без учёта стека;
- при равенстве сначала берётся элемент из левой части.

## Medium 2. Стабильное слияние событий

Два списка событий уже отсортированы по полю `timestamp`. Событие представлено словарём:

```python
{"timestamp": 120, "source": "bank", "id": "a"}
```

Реализуйте:

```python
def merge_events(left: list[dict], right: list[dict]) -> list[dict]:
    ...
```

Верните единый список по возрастанию `timestamp`. При равных отметках событие из `left` должно идти раньше события из `right`. Исходные списки не изменяйте.

Пример:

```python
left = [
    {"timestamp": 10, "source": "a", "id": "a1"},
    {"timestamp": 20, "source": "a", "id": "a2"},
]
right = [
    {"timestamp": 20, "source": "b", "id": "b1"},
    {"timestamp": 30, "source": "b", "id": "b2"},
]
assert [event["id"] for event in merge_events(left, right)] == [
    "a1", "a2", "b1", "b2"
]
```

Ограничения:

- оба входа отсортированы;
- суммарная длина не превосходит `200_000`;
- повторная сортировка объединённого списка запрещена.

Критерии проверки:

- каждый вход просматривается не более одного раза;
- сложность `Θ(N + M)` по времени и `Θ(N + M)` для результата;
- правило равных ключей реализовано явно.

## Hard 1. Число инверсий

Инверсия — пара индексов `i < j`, для которой `values[i] > values[j]`.

Реализуйте:

```python
def count_inversions(values: list[int]) -> int:
    ...
```

Верните число инверсий за `O(N log N)`, модифицировав merge sort: когда элемент правой части переносится раньше оставшихся элементов левой, он образует инверсию с каждым из них.

Примеры:

```python
count_inversions([]) == 0
count_inversions([1, 2, 3]) == 0
count_inversions([3, 2, 1]) == 3
count_inversions([2, 4, 1, 3, 5]) == 3
```

Ограничения:

- `0 <= len(values) <= 200_000`;
- одинаковые значения не образуют инверсию;
- квадратичный перебор пар запрещён.

Критерии проверки:

- подсчёт встроен в линейное слияние;
- исходный список не изменяется;
- временная сложность `O(N log N)`, дополнительная память `O(N)`.
