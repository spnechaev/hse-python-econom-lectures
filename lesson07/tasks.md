# Занятие 07. Задачи для самостоятельного решения

Каждое решение оформляется как функция с указанной сигнатурой. Функция возвращает результат и не использует `input` или `print`.

## Easy 1. Число операций по категориям

Реализуйте функцию:

```python
def count_categories(categories: list[str]) -> dict[str, int]:
    ...
```

Для каждой категории верните число её появлений.

Пример:

```python
assert count_categories(["еда", "такси", "еда", "связь", "еда"]) == {
    "еда": 3,
    "такси": 1,
    "связь": 1,
}
```

Ограничения:

- `0 <= len(categories) <= 200_000`;
- регистр и пробелы внутри названия значимы;
- сортировать вход не требуется.

Критерии проверки:

- пустой список даёт пустой словарь;
- счётчик создаётся при первом появлении и увеличивается при следующих;
- ожидаемая временная сложность `O(N)`.

## Easy 2. Уникальные клиенты в порядке появления

Реализуйте:

```python
def unique_clients(client_ids: list[str]) -> list[str]:
    ...
```

Верните каждый идентификатор один раз, сохранив порядок его первого появления.

Пример:

```python
assert unique_clients(["c-2", "c-1", "c-2", "c-3", "c-1"]) == [
    "c-2", "c-1", "c-3"
]
```

Ограничения:

- `0 <= len(client_ids) <= 200_000`;
- нельзя проверять наличие перебором результирующего списка.

Критерии проверки:

- используется отдельное множество уже встреченных идентификаторов;
- сохраняется порядок первого появления;
- ожидаемая временная сложность `O(N)`, дополнительная память `O(N)`.

## Easy 3. Индекс транзакций

Транзакции представлены словарями с уникальным полем `id`. Реализуйте:

```python
def index_transactions(transactions: list[dict]) -> dict[str, dict]:
    ...
```

Верните словарь `id -> транзакция`. При повторном идентификаторе поднимите `ValueError`. Исходные словари копировать не нужно.

Пример:

```python
transactions = [
    {"id": "t-10", "amount": 700},
    {"id": "t-11", "amount": 250},
]
index = index_transactions(transactions)
assert index["t-11"]["amount"] == 250
```

Ограничения:

- `0 <= len(transactions) <= 200_000`;
- у каждой записи есть строковое поле `id`.

Критерии проверки:

- дубликат обнаруживается до замены старой записи;
- поиск по готовому индексу не требует просмотра списка;
- ожидаемая временная сложность построения `O(N)`.

## Medium 1. Объединение профилей и балансов

Профиль содержит `client_id` и `name`, баланс — `client_id` и `balance`. Реализуйте:

```python
def attach_balances(profiles: list[dict], balances: list[dict]) -> list[dict]:
    ...
```

Верните новые словари профилей с добавленным полем `balance`, сохранив порядок `profiles`. Если для клиента нет баланса или один `client_id` повторяется в `balances`, поднимите `ValueError`.

Пример:

```python
profiles = [
    {"client_id": "c-1", "name": "Анна"},
    {"client_id": "c-2", "name": "Борис"},
]
balances = [
    {"client_id": "c-2", "balance": 300},
    {"client_id": "c-1", "balance": 120},
]
assert attach_balances(profiles, balances) == [
    {"client_id": "c-1", "name": "Анна", "balance": 120},
    {"client_id": "c-2", "name": "Борис", "balance": 300},
]
```

Ограничения:

- суммарно не более `300_000` записей;
- вложенный перебор двух списков запрещён;
- исходные записи не изменяются.

Критерии проверки:

- балансы сначала индексируются по `client_id`;
- результат строится одним проходом по профилям;
- ожидаемое время `O(N + M)`, память `O(M)` без учёта результата.

## Medium 2. Число различных клиентов в окне

Дан хронологический список идентификаторов клиентов и размер окна `window`. Реализуйте:

```python
def distinct_in_windows(client_ids: list[str], window: int) -> list[int]:
    ...
```

Для каждого непрерывного окна длины `window` верните число различных идентификаторов.

Пример:

```python
assert distinct_in_windows(["a", "b", "a", "c", "b"], 3) == [2, 3, 3]
```

Ограничения:

- `1 <= window <= len(client_ids) <= 200_000`;
- пересчитывать множество каждого окна с нуля запрещено.

Критерии проверки:

- словарь хранит частоты только текущего окна;
- уходящий элемент удаляется из словаря при нулевой частоте;
- ожидаемая временная сложность `O(N)`, память `O(window)`.

## Hard 1. Таблица методом цепочек

Реализуйте учебную хеш-таблицу без использования `dict` и `set` для хранения пар. Таблица — список корзин, каждая корзина — список пар `[key, value]`.

```python
def make_table(capacity: int = 8) -> list[list[list]]:
    ...

def table_put(table: list[list[list]], key, value) -> bool:
    ...

def table_get(table: list[list[list]], key):
    ...

def table_delete(table: list[list[list]], key) -> bool:
    ...

def table_resize(table: list[list[list]], new_capacity: int) -> list[list[list]]:
    ...
```

`table_put` возвращает `True`, если добавлен новый ключ, и `False`, если значение существующего ключа заменено. `table_get` поднимает `KeyError` для отсутствующего ключа. `table_delete` сообщает, был ли ключ найден. При изменении размера каждая пара должна быть помещена заново: старый номер корзины переносить нельзя.

Пример:

```python
table = make_table(2)
assert table_put(table, 1, "one") is True
assert table_put(table, 3, "three") is True  # 1 и 3 попадают в одну корзину
assert table_put(table, 1, "ONE") is False
assert table_get(table, 1) == "ONE"
assert table_delete(table, 3) is True
table = table_resize(table, 8)
assert table_get(table, 1) == "ONE"
```

Ограничения:

- `capacity` и `new_capacity` положительны;
- ключи хешируемы;
- номер корзины вычисляется как `hash(key) % len(table)`;
- внутри корзины допустим линейный поиск.

Критерии проверки:

- коллизия не уничтожает существующую пару;
- равный ключ заменяет значение, а не создаёт дубль;
- поиск и удаление сравнивают и хеш, и ключ через `==`;
- `table_resize` выполняет рехеширование всех пар;
- есть тесты на пустую корзину, коллизию, замену, отсутствие ключа и resize.
