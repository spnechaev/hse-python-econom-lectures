Исключение — необязательная задача `first_missing_positive`, в которой входной список разрешено изменять. Вход соответствует ограничениям: дополнительные проверки формата не требуются.

В оценках сложности считаем сравнение и вычисление хеша коротких строк и небольших целых чисел операциями постоянной стоимости. Ожидаемое время означает хорошее распределение ключей во встроенных `dict` и `set`.

## Easy 1. Поменять ключи и значения местами

Справочник связывает имя с городом. Постройте обратный справочник: каждому городу должен соответствовать список всех имён из этого города. Совпадающие города не должны приводить к потере имён.

```python
def invert_mapping(mapping: dict[str, str]) -> dict[str, list[str]]:
    ...
```

Имена внутри каждого списка идут в том порядке, в котором ключи встречаются в исходном словаре. Порядок городов в результате не проверяется. Пустой справочник даёт `{}`. Списки результата должны быть новыми и независимыми друг от друга.

Примеры:

```python
assert invert_mapping({
    "Аня": "Тула",
    "Борис": "Омск",
    "Вера": "Тула",
}) == {
    "Тула": ["Аня", "Вера"],
    "Омск": ["Борис"],
}
assert invert_mapping({}) == {}
assert invert_mapping({"Аня": "Тула", "Борис": "Тула"}) == {
    "Тула": ["Аня", "Борис"],
}
```

Ограничения:

- до `200_000` пар;
- имена и города — непустые строки длиной до 30 символов;
- регистр и пробелы значимы.

Критерии проверки:

- каждое исходное имя встречается в результате ровно один раз;
- несколько имён с одинаковым городом сохраняются вместе и в нужном порядке;
- исходный словарь не изменяется;
- ожидаемое время `O(N)`, дополнительная память `O(N)`, включая результат.

## Easy 2. Ровно две встречи

Есть списки участников трёх встреч. В одном списке имя может встретиться несколько раз: это повторная запись об участии, а не ещё одна встреча. Верните множество людей, которые были **ровно на двух** встречах. Участники всех трёх встреч в ответ не входят.

```python
def in_exactly_two(
    first: list[str], second: list[str], third: list[str]
) -> set[str]:
    ...
```

Примеры:

```python
assert in_exactly_two(
    ["Аня", "Борис", "Аня", "Вера"],
    ["Борис", "Вера", "Глеб"],
    ["Вера", "Глеб", "Даша"],
) == {"Борис", "Глеб"}
assert in_exactly_two(["Аня", "Аня"], [], []) == set()
assert in_exactly_two(["Аня"], ["Аня"], ["Аня"]) == set()
assert in_exactly_two([], [], []) == set()
```

Ограничения:

- суммарно не более `300_000` записей;
- имена — непустые строки длиной до 30 символов;
- использовать `dict` и `Counter` нельзя.

Критерии проверки:

- повторные записи в пределах одной встречи не меняют ответ;
- люди, посетившие одну или три встречи, исключены;
- возвращается именно множество, исходные списки не изменяются;
- ожидаемое время `O(N)` и дополнительная память `O(K)`, где `N` — суммарная длина списков, `K` — число разных имён.

## Easy 3. Сначала купить, потом продать

Список содержит цену одного товара по дням, в хронологическом порядке. Можно один раз купить товар и один раз продать его **в более поздний день**. Верните наибольшую возможную прибыль. Если выгодной сделки нет, можно ничего не покупать: ответ `0`.

```python
def max_profit(prices: list[int]) -> int:
    ...
```

Прибыль — цена продажи минус цена покупки. Комиссий и других расходов нет. Для пустого списка и одного дня верните `0`.

Примеры:

```python
assert max_profit([7, 1, 5, 3, 6, 4]) == 5
assert max_profit([9, 1]) == 0
assert max_profit([1, 9]) == 8
assert max_profit([4, 4, 4]) == 0
assert max_profit([]) == 0
assert max_profit([5]) == 0
```

Ограничения:

- до `200_000` дней;
- цены — целые числа от `0` до `10**9`;
- нельзя сортировать данные, использовать `dict` или `set`.

Критерии проверки:

- покупка всегда предшествует продаже;
- убывающие и постоянные цены дают `0`;
- исходный порядок и список сохраняются;
- время `O(N)`, дополнительная память `O(1)`.

## Medium 1. Самая длинная серия дней

В журнале записаны номера дней, когда сервис работал без сбоев. Записи перемешаны, один день может встретиться несколько раз. Найдите самый длинный диапазон целых дней **без пропусков**, каждый из которых присутствует в журнале.

```python
def longest_streak(days: list[int]) -> tuple[int, int] | None:
    ...
```

Верните включённые границы диапазона `(начало, конец)`. Если серий максимальной длины несколько, выберите ту, которая начинается раньше. Для пустого входа верните `None`.

Здесь важны номера дней, а не соседство записей в списке. Например, наличие дней `2`, `3`, `4`, `5` образует серию длиной четыре, в каком бы порядке они ни пришли. Повтор одного дня серию не удлиняет.

Примеры:

```python
assert longest_streak([7, 3, 5, 4, 4, 10, 2]) == (2, 5)
assert longest_streak([10, 11, 1, 2]) == (1, 2)
assert longest_streak([0, 0]) == (0, 0)
assert longest_streak([8]) == (8, 8)
assert longest_streak([]) is None
```

Ограничения:

- до `200_000` записей;
- номера дней — целые числа от `0` до `10**9`;
- сортировка запрещена;
- исходный список не изменяется.

Критерии проверки:

- разрывы между сериями учитываются, повторы не влияют на длину;
- при равенстве длин выбирается более раннее начало;
- ожидаемое время `O(N)`, дополнительная память `O(K)`, где `K` — число разных дней;
- большой разрыв между номерами не должен заставлять программу обходить все дни внутри разрыва.

## Medium 2. Полиномиальный хеш без коллизий

На семинаре мы подбирали число ячеек для целых ключей. Теперь ключи — заранее известные различные слова, а длина таблицы `capacity` уже задана. Нужно подобрать основание полиномиального хеша так, чтобы **все эти слова** попали в разные ячейки.

Буквы кодируются числами: `a → 1`, `b → 2`, …, `z → 26`. Код буквы можно получить как `ord(char) - ord("a") + 1`. Для каждого слова начните с `h = 0` и обрабатывайте буквы **слева направо**, на каждом шаге заменяя:

`h = (h * base + код_буквы) % capacity`.

Итоговое `h` — номер ячейки. Это вычисление полинома: до взятия остатков слово `abc` соответствует `1 * base**2 + 2 * base + 3`. Использовать встроенный `hash()` вместо заданной формулы нельзя.

Разрешены целые основания от `2` до `base_limit` **включительно**. Найдите наименьшее подходящее основание и постройте таблицу. Если ни одно основание из диапазона не подходит, верните `None`; менять длину таблицы нельзя.

```python
def build_perfect_table(
    words: list[str], capacity: int, base_limit: int
) -> tuple[int, list[str | None]] | None:
    ...
```

Успешный результат — пара `(base, table)`. Список `table` имеет длину `capacity`: каждое слово находится в ячейке, вычисленной по формуле, свободные ячейки содержат `None`. Для пустого списка слов подходит любое основание, поэтому верните `(2, [None] * capacity)`.

Основание одно для **всех** слов. «Идеальный» здесь означает отсутствие коллизий только на заданном наборе: произвольное новое слово может столкнуться с уже размещённым. Даже если ячеек достаточно, подходящего основания может не быть.

Примеры:

```python
assert build_perfect_table(["ab", "ba", "cc"], 5, 4) == (
    4, ["cc", "ab", None, None, "ba"]
)
assert build_perfect_table(["ab", "ba", "cc"], 5, 3) is None
assert build_perfect_table(["ab", "ba"], 5, 4) == (
    2, ["ba", None, None, None, "ab"]
)
assert build_perfect_table(["a", "b", "ac"], 3, 4) == (3, ["ac", "a", "b"])
assert build_perfect_table(["z"], 5, 2) == (2, [None, "z", None, None, None])
assert build_perfect_table(["a", "c"], 2, 10) is None
assert build_perfect_table(["a", "b"], 1, 10) is None
assert build_perfect_table([], 3, 2) == (2, [None, None, None])
```

В первом примере основания `2` и `3` дают коллизии. При основании `4` слова `ab`, `ba`, `cc` получают позиции `1`, `4`, `0`. Для односимвольных `a` и `c` при длине `2` коллизия сохраняется при любом основании.

Ограничения:

- от `0` до `200` различных непустых слов;
- каждое слово содержит только латинские буквы `a`–`z`, длина — до `20` символов;
- `1 <= capacity <= 1_000`, `2 <= base_limit <= 1_000`;
- нельзя менять заданную формулу, использовать цепочки или сдвигать слово из занятой ячейки в другую;
- исходный список не изменяется.

Критерии проверки:

- основание наименьшее подходящее из разрешённого диапазона и используется для всех слов;
- каждое слово стоит точно на своей позиции, остальные ячейки содержат `None`;
- правильно обрабатываются пустой набор, нехватка ячеек и отсутствие подходящего основания;
- порядок входных слов не влияет на основание и содержимое таблицы;
- достаточно времени `O(A * (L + capacity))` и дополнительной памяти `O(N + capacity)`, включая результат; здесь `A = base_limit - 1` — число разрешённых оснований, `L` — суммарная длина слов, `N` — число слов.

## Hard 1. Minimum missing positive — необязательная задача

Найдите наименьшее **положительное целое число**, которого нет в списке. Отрицательные числа и ноль не влияют на ответ. Повторы не заменяют пропущенные значения.

```python
def first_missing_positive(values: list[int]) -> int:
    ...
```

Требуются **`O(n)` времени и `O(1)` дополнительной памяти**, где `n` — длина списка. В этой задаче **входной список разрешено изменять**. Возвращать изменённый список не нужно: результат функции — одно целое число.

Примеры:

```python
assert first_missing_positive([1, 2, 0]) == 3
assert first_missing_positive([3, 4, -1, 1]) == 2
assert first_missing_positive([7, 8, 9, 11, 12]) == 1
assert first_missing_positive([1, 1, 2]) == 3
assert first_missing_positive([0, -3, -1, 0]) == 1
assert first_missing_positive([1, 2, 3, 4]) == 5
assert first_missing_positive([]) == 1
assert first_missing_positive([1]) == 2
assert first_missing_positive([2]) == 1
```

Ограничения:

- до `200_000` целых чисел от `-10**9` до `10**9`;
- `sorted()` и `.sort()` запрещены;
- нельзя копировать входной список или создавать вспомогательный контейнер, размер которого растёт вместе с входом;
- хеш-контейнеры (`dict`, `set` и их специализированные варианты) запрещены.

Критерии проверки:

- возвращается именно первое отсутствующее положительное число;
- отрицательные числа, нули и повторы обрабатываются корректно;
- для пустого списка ответ равен `1`;
- время линейно по длине входа, дополнительная память постоянна;
- изменение входа допустимо только в этой задаче; остальные задачи сохраняют прежние требования.
