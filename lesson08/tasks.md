## Easy 1. Количество в заявке

Количество приходит из текстового поля. Преобразуйте его в целое число по правилам `int(text)` и верните результат, если он находится в диапазоне от 0 до 100 000 включительно. Пробелы по краям, знак `+` и ведущие нули допустимы, как при обычном вызове `int()`.

Если преобразование невозможно или число вне диапазона, поднимите `ValueError`. Подмена ошибочного значения нулём запрещена: нулевая заявка сама по себе допустима.

```python
def parse_quantity(text: str) -> int:
    ...
```

Примеры:

```python
assert parse_quantity("  +007 ") == 7
assert parse_quantity("0") == 0
assert parse_quantity("100000") == 100000

for text in ["", "три", "3.0", "-1", "100001"]:
    try:
        parse_quantity(text)
    except ValueError:
        pass
    else:
        raise AssertionError(f"Ожидался ValueError для {text!r}")
```

Ограничения: длина строки не более 100 символов.

Критерии: возвращается целое число, границы включены; все перечисленные ошибочные значения приводят к `ValueError`. Время — `O(len(text))`, дополнительная память — `O(1)` при заданном ограничении на число.

## Easy 2. Первый доступный товар

В словаре `prices` хранятся цены товаров по кодам. Список `preferred` содержит коды в порядке предпочтения покупателя. Верните пару `(код, цена)` для первого кода, который есть в словаре. Отсутствие отдельного товара не прерывает поиск.

Если ни один код не найден, поднимите `KeyError`. Это правило действует и для пустого списка предпочтений. Цена 0 допустима и не означает отсутствие товара.

```python
def first_available(
    prices: dict[str, int], preferred: list[str]
) -> tuple[str, int]:
    ...
```

Примеры:

```python
assert first_available({"tea": 120, "water": 0}, ["coffee", "water", "tea"]) == ("water", 0)
assert first_available({"tea": 120}, ["tea", "tea"]) == ("tea", 120)

for prices, preferred in [({}, []), ({}, ["tea"]), ({"tea": 120}, ["coffee"])]:
    try:
        first_available(prices, preferred)
    except KeyError:
        pass
    else:
        raise AssertionError("Ожидался KeyError")
```

Ограничения: до 100 000 цен и до 100 000 предпочтений, длина кода не более 50 символов; цены — целые числа от 0 до 10⁹. Повторы в `preferred` разрешены.

Критерии: соблюдён порядок предпочтений, нулевая цена не потеряна, вход не изменён; в среднем `O(n)` времени по длине `preferred`, `O(1)` дополнительной памяти.

## Easy 3. Параметры из JSON

Программа получает параметры в JSON-строке. Если строка не разбирается, можно взять запасные параметры `fallback`. Если строка разбирается, но содержит не словарь, это ошибка формата данных, которую подменять нельзя.

```python
def decode_options(text: str, fallback: dict) -> dict:
    ...
```

Правила:

- если `json.loads(text)` поднимает `json.JSONDecodeError`, верните **новую поверхностную копию** `fallback`;
- если JSON корректен, но верхний уровень не словарь, поднимите `ValueError`;
- если JSON содержит словарь, верните его, включая пустой словарь;
- `fallback` не изменяется; проверять состав его ключей и значений не нужно.

Примеры:

```python
fallback = {"limit": 10, "offset": 0}
result = decode_options('{"limit":}', fallback)
assert result == fallback
assert result is not fallback
result["limit"] = 20
assert fallback == {"limit": 10, "offset": 0}

assert decode_options('{"limit": 0}', fallback) == {"limit": 0}
assert decode_options("{}", fallback) == {}
assert decode_options("", {}) == {}

for text in ["null", "false", "0", "[]", '"options"']:
    try:
        decode_options(text, fallback)
    except ValueError:
        pass
    else:
        raise AssertionError("Корректный JSON не-словарь нужно отклонить")
```

Ограничения: строка длиной до 100 000 символов; JSON, если корректен, имеет глубину вложенности не более 20; в `fallback` не более 10 000 ключей. Применяются обычные правила `json.loads()`.

Критерии: ошибка синтаксиса JSON и недопустимая структура обрабатываются по разным правилам; пустой словарь не заменяется запасными параметрами; результат при неудачном разборе не совпадает с `fallback` по идентичности. Время и дополнительная память — `O(L + k)`, где `L` — длина JSON, `k` — число запасных параметров.

## Medium 1. Команды по счёту

Есть начальный остаток `initial` и список текстовых команд. Каждая команда должна содержать ровно два поля, разделённых `;`:

- `ADD;amount` — пополнить счёт;
- `TAKE;amount` — списать со счёта.

Пробелы по краям каждого поля удаляются. Названия команд регистрозависимы: разрешены только `ADD` и `TAKE`. Сумма разбирается по правилам `int()` и должна быть строго положительной. Списание допустимо, только если денег достаточно.

Верните пару `(остаток, номера_отклонённых_команд)`. Номера начинаются с 1 и идут в исходном порядке. Некорректную команду отклоняйте целиком: она не меняет остаток, а обработка следующих команд продолжается. Пустая строка тоже некорректна; комментариев во входе нет.

```python
def account_report(
    initial: int, commands: list[str]
) -> tuple[int, list[int]]:
    ...
```

Примеры:

```python
commands = [
    "TAKE;30",      # остаток 70
    "TAKE;80",      # недостаточно денег
    "ADD; 20 ",     # остаток 90
    "ADD;zero",     # сумма не разбирается
    "TAKE;90",      # остаток 0
    "ADD;0",        # сумма должна быть положительной
    "ADD;5;extra",  # лишнее поле
]
assert account_report(100, commands) == (0, [2, 4, 6, 7])
assert account_report(0, []) == (0, [])
assert account_report(0, ["TAKE;1", "ADD;10", "TAKE;10"]) == (0, [1])
assert account_report(5, ["", "add;2", "ADD;-1", "TAKE;6", "ADD;2"]) == (7, [1, 2, 3, 4])
```

Ограничения: `0 <= initial <= 10⁹`; не более 100 000 команд, длина каждой до 100 символов. Все успешно разобранные суммы по модулю не превышают 10⁹. Входной список не изменяется.

Критерии: различаются ошибки формата, неизвестная команда, недопустимая сумма и недостаток денег; отклонённая команда не меняет состояние. Не перехватывайте все возможные исключения: неожиданная ошибка программы не должна превращаться в очередной номер в отчёте. Время — `O(L)`, где `L` — общая длина команд; дополнительная память — `O(k)` для списка отклонений.

## Medium 2. Лимиты из открытого файла

Функция получает открытый текстовый поток `source`, расположенный на данных, которые нужно прочитать. Поток может быть обычным файлом или `io.StringIO` — строкой, с которой можно работать как с файлом.

**Функция принимает владение потоком:** после любого выхода из функции, в том числе при ошибке, `source` должен быть закрыт. Для этого используйте `with`. Поток должен поддерживать чтение и работу с `with`, как обычный текстовый файл.

```python
from typing import TextIO

def load_limits(source: TextIO) -> dict[str, int]:
    ...
```

Прочитайте JSON из потока и проверьте данные:

- верхний уровень — словарь;
- каждый ключ — строка, содержащая хотя бы один непробельный символ; имена сохраняются без изменений;
- каждое значение — именно целое число от 0 до 10⁹ включительно;
- значения `true` и `false` в JSON **не считаются целыми лимитами**, как и `1.0`.

Верните прочитанный словарь. Для корректного пустого словаря верните `{}`.

Политика ошибок:

- нарушение перечисленных правил — `ValueError`;
- некорректный JSON — исходный `json.JSONDecodeError`;
- ошибки чтения потока, например `OSError`, должны выходить наружу без подмены;
- даже при любой из этих ошибок поток закрывается;
- пустое содержимое потока — некорректный JSON, а не пустой словарь.

Примеры:

```python
import json
from io import StringIO

source = StringIO('{"food": 1200, "rent": 45000, "other": 0}')
assert load_limits(source) == {"food": 1200, "rent": 45000, "other": 0}
assert source.closed

source = StringIO("{}")
assert load_limits(source) == {}
assert source.closed

for text in ['[]', '{"food": -1}', '{"food": true}', '{"food": 1.0}', '{"  ": 20}']:
    source = StringIO(text)
    try:
        load_limits(source)
    except ValueError:
        pass
    else:
        raise AssertionError("Ожидался ValueError")
    assert source.closed

source = StringIO('{"food":}')
try:
    load_limits(source)
except json.JSONDecodeError:
    pass
else:
    raise AssertionError("Ожидался JSONDecodeError")
assert source.closed
```

Ограничения: JSON длиной до 1 000 000 символов, не более 10 000 ключей, глубина вложенности не более 20. Если JSON нарушает контракт, функция должна его отклонить, а не исправить. Объём памяти для прочитанного JSON допустим; потоковое чтение больших документов в этой задаче не требуется.

Критерии: весь словарь проверен; `bool` не принят за `int`; правильные исключения не подавлены; поток закрыт при успехе, ошибке разбора, ошибке проверки и ошибке чтения. Время и память — `O(L)` по длине JSON.
