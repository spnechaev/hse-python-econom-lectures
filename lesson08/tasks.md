Каждое решение — один файл `.py` с указанной функцией и необходимыми импортами из стандартной библиотеки. Функции возвращают результат или поднимают исключение и не используют `input()` или `print()`.

Типы аргументов соответствуют аннотациям. Проверять ограничения, которые прямо гарантированы в условии, не нужно. Некорректное содержимое, перечисленное в условии, нужно обработать. ## Easy 1. Количество в заявке

Количество приходит из текстового поля. Преобразуйте его в целое число по правилам `int(text)` и верните результат, если он находится в диапазоне от 0 до 100 000 включительно. Пробелы по краям, знак `+` и ведущие нули допустимы, как при обычном вызове `int()`.

Если преобразование невозможно или число вне диапазона, поднимите `ValueError`. Подмена ошибочного значения нулём запрещена: нулевая заявка сама по себе допустима.

```python
def parse_quantity(text: str) -> int:
    ...
```

Примеры:

```python
assert parse_quantity("  +007 ") == 7
assert parse_quantity("0") == 0
assert parse_quantity("100000") == 100000

for text in ["", "три", "3.0", "-1", "100001"]:
    try:
        parse_quantity(text)
    except ValueError:
        pass
    else:
        raise AssertionError(f"Ожидался ValueError для {text!r}")
```

Ограничения: длина строки не более 100 символов.

Критерии: возвращается целое число, границы включены; все перечисленные ошибочные значения приводят к `ValueError`. Время — `O(len(text))`, дополнительная память — `O(1)` при заданном ограничении на число.

## Easy 2. Первый доступный товар

В словаре `prices` хранятся цены товаров по кодам. Список `preferred` содержит коды в порядке предпочтения покупателя. Верните пару `(код, цена)` для первого кода, который есть в словаре. Отсутствие отдельного товара не прерывает поиск.

Если ни один код не найден, поднимите `KeyError`. Это правило действует и для пустого списка предпочтений. Цена 0 допустима и не означает отсутствие товара.

```python
def first_available(
    prices: dict[str, int], preferred: list[str]
) -> tuple[str, int]:
    ...
```

Примеры:

```python
assert first_available({"tea": 120, "water": 0}, ["coffee", "water", "tea"]) == ("water", 0)
assert first_available({"tea": 120}, ["tea", "tea"]) == ("tea", 120)

for prices, preferred in [({}, []), ({}, ["tea"]), ({"tea": 120}, ["coffee"])]:
    try:
        first_available(prices, preferred)
    except KeyError:
        pass
    else:
        raise AssertionError("Ожидался KeyError")
```

Ограничения: до 100 000 цен и до 100 000 предпочтений, длина кода не более 50 символов; цены — целые числа от 0 до 10⁹. Повторы в `preferred` разрешены.

Критерии: соблюдён порядок предпочтений, нулевая цена не потеряна, вход не изменён; в среднем `O(n)` времени по длине `preferred`, `O(1)` дополнительной памяти.

## Easy 3. Параметры из JSON

Программа получает параметры в JSON-строке. Если строка не разбирается, можно взять запасные параметры `fallback`. Если строка разбирается, но содержит не словарь, это ошибка формата данных, которую подменять нельзя.

```python
def decode_options(text: str, fallback: dict) -> dict:
    ...
```

Правила:

- если `json.loads(text)` поднимает `json.JSONDecodeError`, верните **новую поверхностную копию** `fallback`;
- если JSON корректен, но верхний уровень не словарь, поднимите `ValueError`;
- если JSON содержит словарь, верните его, включая пустой словарь;
- `fallback` не изменяется; проверять состав его ключей и значений не нужно.

Примеры:

```python
fallback = {"limit": 10, "offset": 0}
result = decode_options('{"limit":}', fallback)
assert result == fallback
assert result is not fallback
result["limit"] = 20
assert fallback == {"limit": 10, "offset": 0}

assert decode_options('{"limit": 0}', fallback) == {"limit": 0}
assert decode_options("{}", fallback) == {}
assert decode_options("", {}) == {}

for text in ["null", "false", "0", "[]", '"options"']:
    try:
        decode_options(text, fallback)
    except ValueError:
        pass
    else:
        raise AssertionError("Корректный JSON не-словарь нужно отклонить")
```

Ограничения: строка длиной до 100 000 символов; JSON, если корректен, имеет глубину вложенности не более 20; в `fallback` не более 10 000 ключей. Применяются обычные правила `json.loads()`.

Критерии: ошибка синтаксиса JSON и недопустимая структура обрабатываются по разным правилам; пустой словарь не заменяется запасными параметрами; результат при неудачном разборе не совпадает с `fallback` по идентичности. Время и дополнительная память — `O(L + k)`, где `L` — длина JSON, `k` — число запасных параметров.

## Medium 1. Подписи по шаблону

Программа готовит подписи участников по общему шаблону. Для каждой записи нужно подставить значения полей и получить отдельную строку. Если в записи не хватает поля, вызывающий код должен узнать её номер и сохранить исходную причину ошибки.

```python
def render_labels(
    template: str, rows: list[dict[str, str]]
) -> list[str]:
    ...
```

Для подстановки используется метод строки `template.format_map(row)`: он берёт значения из словаря `row` по именам в фигурных скобках. Например, `"{name}: {city}".format_map({"name": "Аня", "city": "Тула"})` возвращает `"Аня: Тула"`. Двойные скобки `{{` и `}}` обозначают обычные скобки в результате. Если поля нет, метод поднимает `KeyError`; если нарушена запись шаблона, он может поднять `ValueError`.

В корректном шаблоне используются только простые имена полей: латинские буквы, цифры и `_`, первый символ — буква или `_`. Индексов, обращений к атрибутам и спецификаторов форматирования нет. Сам шаблон может содержать ошибку в фигурных скобках. Значения в записях — строки; пустые значения и лишние поля допустимы. Скобки внутри значений остаются обычным текстом и повторно не подставляются.

Верните список готовых подписей в исходном порядке. Пустому `rows` соответствует `[]`: в этом случае шаблон не проверяется. Исходные записи не изменяются.

Политика ошибок:

- обрабатывайте записи по порядку и останавливайтесь при первой ошибке;
- если `format_map` поднимает `KeyError`, поднимите новый `ValueError` с сообщением `Запись N: отсутствует поле KEY`, где `N` — номер записи с 1, `KEY` — имя отсутствующего поля;
- исходный объект `KeyError` должен стать **явной причиной** нового исключения: используйте `raise ... from ...`;
- если сам `format_map` поднимает `ValueError`, передайте его наружу без подмены; остальные неожиданные исключения тоже не подменяйте;
- не выполняйте отдельную предварительную проверку всего шаблона: если раньше ошибки скобок метод встретил отсутствующее поле, действует правило для `KeyError`;
- при ошибке частичный список подписей не возвращается.

У исключения есть атрибут `args` — кортеж аргументов, с которыми оно создано. Для отсутствующего поля `city` исходный `KeyError` содержит `args == ("city",)`. После `raise ... from ...` исходное исключение доступно у нового через атрибут `__cause__`. Эти атрибуты позволяют проверить не только сообщение, но и сохранённую причину.

Примеры:

```python
rows = [
    {"name": "Аня", "city": "Тула"},
    {"name": "Боря", "city": "Уфа"},
]
assert render_labels("{name}: {city}", rows) == ["Аня: Тула", "Боря: Уфа"]
assert render_labels("{{{name}}}", [{"name": "Аня"}]) == ["{Аня}"]
assert render_labels("{name}", [{"name": "{city}", "city": "Тула"}]) == ["{city}"]
assert render_labels("{name", []) == []

rows = [{"name": "Аня", "city": "Тула"}, {"name": "Боря"}]
try:
    render_labels("{name}: {city}", rows)
except ValueError as error:
    assert str(error) == "Запись 2: отсутствует поле city"
    assert isinstance(error.__cause__, KeyError)
    assert error.__cause__.args == ("city",)
else:
    raise AssertionError("Ожидался ValueError с исходной причиной")

try:
    render_labels("{name", [{"name": "Аня"}])
except ValueError as error:
    assert error.__cause__ is None
else:
    raise AssertionError("Ожидался ValueError от format_map")

# Отсутствующее поле встречается раньше незакрытой скобки.
try:
    render_labels("{name} {", [{}])
except ValueError as error:
    assert str(error) == "Запись 1: отсутствует поле name"
    assert isinstance(error.__cause__, KeyError)
    assert error.__cause__.args == ("name",)
else:
    raise AssertionError("Ожидался ValueError с причиной KeyError")
```

Ограничения: до 100 000 записей, в каждой до 100 полей; шаблон длиной до 1 000 символов, имена полей длиной до 50 символов, значения — до 1 000 символов. Суммарная длина готовых подписей не превышает 1 000 000 символов.

Критерии: подписи сохраняют порядок записей; при отсутствии поля указан правильный номер и сохранён исходный `KeyError`; ошибки самого шаблона не превращаются в ошибки записи. При обычной средней стоимости доступа к словарю время — `O(n · t + R)`, где `n` — число обработанных записей, `t` — длина шаблона, `R` — суммарная длина полученных подписей; дополнительная память с учётом результата — `O(n + R + t)`.

## Medium 2. Первая разница в двух файлах

Два текстовых файла могут различаться одной строкой или тем, что один закончился раньше. Найдите первую разницу, не читая оставшуюся часть файлов после неё.

Функция получает **два разных открытых текстовых потока** `first` и `second`. Чтение начинается с их текущих позиций. Поток может быть обычным файлом или `io.StringIO` — строкой, с которой можно работать как с файлом. Создавать собственные файлы для решения и проверки не нужно.

```python
from typing import TextIO

def first_difference(
    first: TextIO, second: TextIO
) -> tuple[int, str | None, str | None] | None:
    ...
```

Читайте потоки с помощью `readline()`. Этот метод возвращает очередную строку вместе с завершающим `\n`, если он есть; только в конце потока возвращается `""`. Пустая строка файла — это `"\n"`, она не означает конец потока.

Сравнивайте строки **точно как их вернул `readline()`**, включая пробелы и символы перевода строки. Не применяйте `strip()` и не добавляйте отсутствующий перевод строки.

- Если строки различаются, верните тройку `(номер, строка_из_first, строка_из_second)`. Номер начинается с 1 относительно текущих позиций потоков.
- Если один поток уже закончился, вместо его строки в тройке должно быть `None`.
- Если весь оставшийся текст совпадает, верните `None`. Это правило действует и для двух пустых потоков.

**Функция принимает владение обоими потоками:** при любом выходе оба должны быть закрыты. Используйте `with` для обоих потоков. Закрытие требуется при полном совпадении, раннем возврате первой разницы и исключении во время чтения. Ошибки чтения, например `OSError`, должны выходить наружу без подмены: проверяется, что это тот же объект исключения, а не новое исключение такого же типа. Вход в контекст и закрытие переданных потоков завершаются без ошибок.

Нельзя читать потоки целиком через `read()`, `readlines()` или `list()`. Пользуйтесь `readline()` и прекращайте чтение сразу после первой различающейся пары.

Примеры:

```python
from io import StringIO

first = StringIO("чай\nсоль\n")
second = StringIO("чай\nсахар\n")
assert first_difference(first, second) == (2, "соль\n", "сахар\n")
assert first.closed and second.closed

first = StringIO("чай\n")
second = StringIO("чай\n\n")
assert first_difference(first, second) == (2, None, "\n")
assert first.closed and second.closed

first = StringIO("чай\n\n")
second = StringIO("чай\n")
assert first_difference(first, second) == (2, "\n", None)
assert first.closed and second.closed

first = StringIO("чай")
second = StringIO("чай\n")
assert first_difference(first, second) == (1, "чай", "чай\n")
assert first.closed and second.closed

for text in ["", "чай\nсоль\n"]:
    first = StringIO(text)
    second = StringIO(text)
    assert first_difference(first, second) is None
    assert first.closed and second.closed

# Уже прочитанные строки не входят в сравнение и нумерацию.
first = StringIO("пропустить\nчай\n")
second = StringIO("чай\n")
assert first.readline() == "пропустить\n"
assert first_difference(first, second) is None
assert first.closed and second.closed
```

Ограничения: в каждом потоке не более 100 000 оставшихся строк, длина строки с учётом `\n` не более 1 000 символов. Потоки поддерживают `readline()`, закрытие и работу с `with`, как обычные открытые текстовые файлы.

Критерии: найдена первая разница, конец потока не перепутан с пустой строкой файла, завершающий `\n` учитывается; лишние строки после первой разницы не прочитаны; оба потока закрыты на всех путях выхода, исходные ошибки чтения не подавлены. Время — `O(L)`, где `L` — число реально прочитанных символов плюс число вызовов `readline()`; дополнительная память — `O(m)`, где `m` — максимальная суммарная длина одной сравниваемой пары строк.
